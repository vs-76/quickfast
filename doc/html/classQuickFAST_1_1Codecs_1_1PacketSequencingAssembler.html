◆ messageAvailable()

virtual int QuickFAST::Codecs::DataSource::messageAvailable ( )
virtualinherited

Is a complete message available?

This method can be used to avoid beginning the decode process until a complete message is available for decoding.

For synchronous decoding:

  • If getByte() is designed to block this message can just return 1 meaning "it *will* be available when needed."
  • If getByte() is nonblocking then this method should block until a complete has arrived, then return 1.
  • For synchronous operation this method should never return 0.

For asynchronous decoding:

  • This method should be called in an event loop or reactor. It should not block; just return 0 until there is a complete message available, then return 1. For asynchronous operation, getByte should never block.
Returns
-1 if end of data; 0 if no message available now; 1 if a message should be decoded

Control Echo for debugging/diagnostics.

As an aid to debugging and or diagnosing problems, the DataSource can echo every input byte to an "echo" stream, either in binary or hex. Either HEX, RAW, or NONE should be specified. If NONE is selected, then the message and field info can be used to find message and field boundaries in the input data stream.

Parameters

echoTypeEither RAW, HEX, or NONE to dump raw or "human readable" data to output.

◆ setGapTimeoutLimit()

void QuickFAST::Codecs::PacketSequencingAssembler::setGapTimeoutLimit ( size_t limit)
inline

Give up on a gap after this many consecutive recovery timeouts.

Zero, the default, means never give up, which is the historical behaviour: a gap the feed keeps promising to fill is re-polled every ten milliseconds for as long as it says so.

Parameters
limitis the number of consecutive timeouts to tolerate.
Example
assembler.setGapTimeoutLimit(100); // escalate after about a second

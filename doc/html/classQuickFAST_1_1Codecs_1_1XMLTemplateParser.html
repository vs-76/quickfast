Detailed Description

Parse a template file into a TemplateRegistry.

Notes on parsing XML Templates

The goal is to populate a TemplateRegistry with a set of Template objects. A Template is a SegmentBody. A SegmentBody is an ordered collection of FieldInstructions.

The intent is to have almost every element in the XML template file correspond to an object, and have the attributes for those elements correspond to method calls on those objects. In practice, some elements correspond to method calls on the enclosing element.

The mapping:

XML element                 Object or method
========================    ================
<templates>                 TemplateRegistry
<template>                  Template
                            -- add to registry via TemplateRegistry::addTemplate
<typeRef>                   setApplicationType() on enclosing element.

Field instructions          add to Template via addInstruction() method.
  <int32>                   FieldInstructionInt32
  <int64>                   FieldInstructionInt64
  <uint32>                  FieldInstructionUInt32
  <uint64>                  FieldInstructionUInt64
  <decimal>                 FieldInstructionDecimal
   <exponent>               FieldInstructionExponent
                              add via setExponentInstruction()
   <mantissa>               FieldInstructionMantissa
                              add via setMantissaInstruction()
  <string charset="ascii">  FieldInstructionAscii [note charset is optional here]
  <string charset="unicode"> FieldInstructionUtf8
  <byteVector>              FieldInstructionByteVector
  <group>                   FieldInstructionGroup (starts new Segment)
  <sequence>                FieldInstructionSequence (starts new Segment)
    <length>                FieldInstructionUInt32 added to sequence via
                              addLengthInstruction() method.
  <templateRef>             FieldInstructionTemplateRef

Field operations            add to FieldInstruction via setFieldOp() method
    value=                    setValue() method on FieldOp
    key=                      setKey() method on FieldOp
    nsKey=                    setKeyNamespace() method on FieldOp
    dictionary=               setDictionaryName() method on FieldOp
  no operation specified    FieldOpNop (set by default)
  <constant>                FieldOpConstant
  <default>                 FieldOpDefault
  <copy>                    FieldOpCopy
  <delta>                   FieldOpDelta
  <increment>               FieldOpIncrement
  <tail>                    FieldOpTail

Commmon attributes
  name=                     construction parameter or setName()
  ns=                       construction parameter or setNamespace()
  id=                       setId()
  presence="mandatory"      setPresence(true)  (the default)
  presence="optional"       setPresence(false)

Notes:

<typeRef> The typeref instruction should really be an attribute on the Template, FieldInstructionGroup, or FieldInstructionSequence. Thus rather than defining FieldInstructionTypeRef, there is a method: setApplicationType() on the SegmentBody object, and a typeref element should trigger a call to that method. Note that only one typeref is allowed per segment.

<templateRef> A FieldInstructionGroup contains a SegmentBody for the fields that are defined within the group. When the start element of a Group or Sequence is encountered, a new Codecs::SegmentBody should be created. Parsing should continue into that SegmentBody until the end of the Group.

<sequence> A FieldInstructionSequence contains a SegmentBody for the fields that are defined within the sequence. When the start element of a Sequence is encountered, a new Codecs::SegmentBody should be created.

If a <length> instruction is encountered while decoding a segment, a FieldInstructionUInt32 should be created, honoring any attributes in the instruction element. This FieldInstruction should be added to the segment using setLengthInstruction rather than the normal addInstruction method.

The segment will detect illegal uses of the <length> instruction. If No length instruction is specified, the Sequence will automatically handle the default length.

Multithreading Note: This class was designed under the assumption that it would be run once during initialization. There are no guarantees that template parsing is thread-safe. The resulting template repository, however, can be safely shared between threads.

Example
Parse a template file once at startup and share the result:
std::ifstream templateFile("templates.xml");
if(!templateFile.good())
{
throw std::runtime_error("Cannot open templates.xml");
}
QuickFAST::Codecs::XMLTemplateParser parser;
QuickFAST::Codecs::TemplateRegistryPtr registry = parser.parse(templateFile);
// One registry may back any number of Decoder / Encoder objects, including
// ones running on different threads.
QuickFAST::Codecs::Decoder decoder(registry);
